# 工作流交付同步清单

本轮基线：模板提交 `5ce40400743a1415c5031400d8684fc9b50a77d5`。目标是交付当前可复用的工作流，保留模板已验证和后续修订的 skill 行为。下列冲突来自本轮尚未提交的改动，不代表已提交模板缺少这些能力。

## 缺失与冲突处理

| 项目       | 发现                                             | 本轮处理                                                                     |
| ---------- | ------------------------------------------------ | ---------------------------------------------------------------------------- |
| API 阶段   | 下载稿把 API 校验放在拆票阶段                    | 恢复澄清阶段完成 API 输入、核验、缺口追问；规划复用已批准契约                |
| 阶段触发   | 改成规划后自动实现                               | 恢复三个独立人工调用入口；规划批准不等于实现授权                             |
| 票集       | 允许零票                                         | 保留至少一张票、全量批准、原生父子和阻塞关系                                 |
| 调度       | 改成全程串行                                     | 保留独立任务默认最多两个 worker，集成与验证串行                              |
| 标签       | 新增 requirements-ready 等并将 wontfix 当暂停    | 恢复已提交五个互斥主状态及 Spec、waiting-for-human 辅助标签                  |
| 输入承载   | 简化为缺材料一律不建 Issue                       | 保留最小输入门槛、七节草案、外部 Issue 原文保留及 Agent Brief                |
| 后续微调   | 规格纠错、恢复和清理可能被旧设计覆盖             | 自有 skills/common、配置及锁文件恢复已提交字节；保留现有纠错与 PR 后安全清理 |
| 手册       | 背景说明与实际 skill 规则混用                    | 重写当前手册及流程图，名称统一为 workflow-*，附来源决策说明                  |
| 接入       | 说明沿用错误标签及自动接续                       | 修正接入步骤，明确可移植文件、仓库身份、依赖和状态边界                       |
| 完整性检查 | 只检查锁中已有项，遗漏条目可能漏检               | 校验实际全部 skill 文件与锁清单严格一致                                      |
| 引用       | 自有 skill/common 相对 Markdown 引用断裂可能漏检 | 增加引用存在性及仓库内路径检查                                               |
| 验证证据   | 历史 POC 容易误认为本版验收                      | 区分离线工程回归、历史行为试验及目标仓库真实流程验收                         |

当前用户明确的交付目标和本清单记录的决策优先；可执行协议以模板 skills、common、项目配置和规则为基线。研究项目 `flow-v2/workflow-sharing-design.md`（2026-09-21）和 `skills-design.md` 同时明确 API 在第一阶段完成；模板后续提交又增加输入承载、规格纠错及安全清理，不用研究稿覆盖这些改进。

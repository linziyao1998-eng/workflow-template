# Implement the approved ticket graph

Independent human-invoked stage adapted from Matt implement-spec. Read [runtime](../common/runtime.md), [version](../common/version.md), [records](../common/records.md) and project rules. The input is a parent Spec plus the entire approved ticket set and explicit implementation authorization. The implementer role is not a call to the upstream implement skill.

1. **Gate execution.** Reread current spec/carrier/approval, full verified plan and every ticket. Require current Spec + ready-for-agent, matching approved scope/acceptance, complete publication, valid dependencies and actual human implementation authorization. Distinguish legitimate dependency removal from scope edits. An arbitrary subset cannot stand for the full plan. Scope or approval drift at this gate is an execution blocker; follow the label and handoff boundary in [recovery.md](references/recovery.md). Before returning from a failed entry gate, persist the pause reason, evidence and resume point in execution.json even when no worker or delivery branch has been created; leave unestablished fields null. Resolve required methods and project checks before dispatch.
2. **Prepare/recover.** Inspect actual Git state and preserve existing work. On first run establish a fixed base SHA and delivery branch, persistent execution record and ignored state directory. Create no PR yet. On resumption follow [recovery.md](references/recovery.md); after human-blocker wind-down require explicit resume authorization.
3. **Dispatch the frontier.** Tickets whose every predecessor has been integrated and verified may run. Default maximum is two implementer workers, reduced for host capacity or actual shared-resource conflicts; human adjustments still respect capacity. Dispatch in independent worktrees based on the current delivery branch containing all predecessors. Read and send the [worker contract](references/ticket-worker.md) with exact context pointers and approved test decisions. Keep code-writing workers isolated; do not have them update shared records or tracker state.
4. **Integrate serially.** One at a time, inspect a worker's commits, merge into the delivery branch and run target-project changed-scope checks and applicable unit/integration tests on that integrated result. Persist merged-unverified before validation. Failed or incomplete validation leaves the ticket incomplete. Resolve stale branches/conflicts against current delivery code; preserve unfinished work.
5. **Advance dependencies.** Only verified integration permits marking the ticket complete locally and removing its satisfied native blocking links from successors. Preserve other blockers and original graph. Keep Issues open. Recompute frontier after each completed integration.
6. **Review the whole implementation.** After all tickets verify, commit all intended code and invoke configured code-review against the fixed base and current HEAD, supplying exact approved spec and ticket references. Independent Standards and Spec reviewers inspect actual committed code. Fix valid findings with a worker, run corresponding tests, commit fixes and independently review the fixes/affected behavior. Record reasons for rejected findings. Respect host capacity when scheduling reviewers.
7. **Run full project gates.** Execute the configured full checks and applicability rules against final code. Repair task-caused failures. Code changes require independent review of fixes and renewed applicable gates; unchanged code after environment recovery can reuse still-valid review. Historical/environment failures remain failures requiring a specific blocker report, not a successful gate.
8. **Deliver.** Only when independent review and required gates cover final HEAD, push and create/update a formal PR. Verify base/head and closure references for parent and every ticket. On uncertain PR creation read existing PRs for the delivery branch before retrying. Return PR and evidence; do not monitor CI or close Issues early. Human merge owns closure through verified references.
9. **Clean up.** Remove only integrated disposable worktrees with no unsaved work. Retain durable evidence and all unfinished branches/worktrees.

At any human-requiring blocker, use the global wind-down in recovery.md: stop new dispatch and subsequent merges, save in-flight work, preserve primary issue state, and report the exact recovery point. Ordinary dependency wait or unavailable dev API with a valid fixture strategy is not itself such a blocker.
